Three Core Empirical Findings (From Audited N=100 Test Benchmark)

  • 1. PTM Preserves Critical Facts Through Compression: Numbers, negations, and percentages achieved 100.0% survival (1,667/1,667 numbers, 69/69 negations, 6/6 percents). Dates and currency achieved 99.7% and 85.7% exact span survival, and 100.0% word/digit-level survival after punctuation normalization (0 constituent words dropped across all 120 missed date spans).
  • 2. Retrieval Completeness Dominates Accuracy: When all gold paragraphs were retrieved in the top-5 (49% of test queries), Large tier accuracy reached 85.71% [75.51, 93.93] and Small reached 57.14% [42.86, 71.43]. When retrieval missed at least one gold paragraph (51% of test), Large accuracy collapsed to 11.76% [3.92, 21.57] and Small to 19.61% [9.80, 31.37].
  • 3. Cascade Routing & Latency Limits: At N=100 test queries, learned routers did not statistically significantly beat cost-matched random routing (paired 95% CIs span zero). Context compression on CPU adds ~6.87s latency overhead, making it a token (~40%) and cost (~36%) optimization, rather than a wall-clock latency saving on free-tier APIs.

About OptiRAG-lite

OptiRAG-lite is an end-to-end empirical research project designed to explore cost-accuracy-latency trade-offs in Retrieval-Augmented Generation (RAG) pipelines under strict zero-budget constraints ($0 actual project spend).

Pipeline Architecture

The system integrates three core optimization stages:

  1. Dense Retrieval & Telemetry Extraction: Encodes passages with sentence-transformers/all-MiniLM-L6-v2 and queries a flat FAISS index over HotpotQA passages. Computes 8 low-dimensional retrieval confidence metrics (top-1 score, score gap, entropy, chunk similarity, token volume).
  2. Confidence-Based Cascade Routing: Evaluates query difficulty using train-calibrated classifiers. Queries likely to be answered correctly by the small tier stay with the small model; challenging multi-hop queries escalate to the large tier.
  3. Protected Token Mask (PTM) Context Compression: Uses microsoft/llmlingua-2-bert-base-multilingual-cased-meetingbank to prune 40-50% of peripheral tokens while enforcing hard regex retention of high-entropy entities (dates, currency, negations, numbers).

Models & Quotas

  • Small Tier: allam-2-7b via Groq Cloud free tier (30 RPM, 6,000 TPM limit). Cost modeled via an 8B-class list price proxy ($0.05 / $0.08 per 1M tokens).
  • Large Tier: gemini-3.5-flash-lite via Google AI Studio free tier (15 RPM, 250,000 TPM, provisional 500 RPD). Modeled at official list rates ($0.30 / $2.50 per 1M tokens).
  • Embedding: all-MiniLM-L6-v2 (384-dimensional dense vectors, local CPU).
  • Compression: LLMLingua-2 BERT-base (local CPU, 2 threads).

Project Limitations

  • Sample Size: 200 train queries and 100 test queries. With N=100 test queries, 95% bootstrap confidence intervals span approximately ±9 percentage points.
  • Small Model Capacity: ALLaM-2-7B is primarily optimized for Arabic-English tasks and achieves 38.0% accuracy on multi-hop HotpotQA English questions.
  • Simulated Costs: All pricing is simulated based on vendor list price sheets; zero actual currency was billed.
  • Static Replay: This web demonstration replays precomputed, cryptographically verified cached inference traces without executing live network requests.
